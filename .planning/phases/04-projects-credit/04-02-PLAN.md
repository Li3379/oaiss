# Plan 04-02: Credit Score + Level Evaluation + Trade Restriction Enforcement

**Status**: PENDING
**Wave**: 2 (depends on 04-01 for enterprise data)
**Requirements**: CRED-01, CRED-02, CRED-03, CRED-04, CRED-05
**Estimated Duration**: 15-20 minutes

## Goal

Verify credit score viewing, score history, level evaluation thresholds (WARNING at 40, FROZEN at 20), trade restriction enforcement, and admin deduct/bonus operations.

## Requirements Coverage

| Req | Description | Test Method |
|-----|-------------|-------------|
| CRED-01 | View credit score and score change history | API: GET /credit/my-score, GET /credit/history |
| CRED-02 | Credit score levels correctly evaluated (EXCELLENT/GOOD/WARNING/DANGER/FROZEN) | API: POST /credit/deduct multiple times, check level transitions |
| CRED-03 | Trade restriction when score < 40 | API: GET /credit/check-permission/{id} after deduction below 40 |
| CRED-04 | Account frozen when score < 20 | API: POST /credit/deduct below 20, verify accountFrozen=true |
| CRED-05 | Admin bonus points and re-evaluation | API: POST /credit/bonus, POST /credit/evaluate/{id} |

## Implementation Steps

### Step 1: Create test script `scripts/credit-score-test.sh`

**Authentication**:
```bash
# Login enterprise001, admin
# Extract tokens
# Get enterprise001's enterpriseId from /credit/my-score response
```

**Test CRED-01: View score and history**
```
1. GET /api/v1/credit/my-score (as enterprise001)
   Assert: code=200, data.score present (integer), data.level present
   Record: initialScore

2. GET /api/v1/credit/history?page=1&size=20 (as enterprise001)
   Assert: code=200, response is paginated (data.totalElements or data.content present)
```

**Test CRED-02: Level evaluation through deductions**
```
3. POST /api/v1/credit/deduct (as admin)
   Body: { "enterpriseId": E1_ID, "eventType": 3, "description": "Minor violation test" }
   eventType=3 = MINOR_VIOLATION = -10 points
   Assert: code=200, data.score = initialScore - 10, data.level matches CreditLevelEnum.fromScore()
   Record: scoreAfterFirstDeduct

   Repeat deductions until score drops below each threshold:
   - Score ≥ 80: EXCELLENT
   - Score 60-79: GOOD
   - Score 40-59: WARNING (also tradeRestricted=true)
   - Score 20-39: DANGER (tradeRestricted=true)
   - Score < 20: FROZEN (accountFrozen=true, tradeRestricted=true)

4. Use eventType=4 (MAJOR_VIOLATION, -30) to speed up deduction if needed
   Use eventType=1 (DATA_FALSIFICATION, -20) for larger drops

5. After each deduction, assert:
   - data.level matches expected level for score range
   - data.tradeRestricted matches: score < 40 → true, score ≥ 40 → false
   - data.accountFrozen matches: score < 20 → true, score ≥ 20 → false
```

**Test CRED-03: Trade restriction at score < 40**
```
6. GET /api/v1/credit/check-permission/{enterpriseId} (any token)
   When score ≥ 40: Assert response=true
   When score < 40: Assert response=false
   (Score should already be < 40 from Step 3-4 deductions)
```

**Test CRED-04: Account frozen at score < 20**
```
7. Continue deductions until score < 20
   GET /api/v1/credit/{enterpriseId} (as admin)
   Assert: data.accountFrozen=true, data.level="FROZEN"
```

**Test CRED-05: Admin bonus + re-evaluation**
```
8. POST /api/v1/credit/bonus?enterpriseId={E1_ID}&points=80&description=Recovery (as admin)
   Assert: code=200, data.score > 40 (restored above WARNING threshold)
   Assert: data.tradeRestricted=false (thresholds recalculated)
   Assert: data.accountFrozen=false

9. POST /api/v1/credit/evaluate/{enterpriseId} (as admin)
   Assert: code=200, data.level matches current score range
```
