# Plan 05-01: Digital Signatures Test Script

**Phase:** 5 — Supporting Domains
**Script:** `scripts/sign-test.sh`
**Requirements:** SIGN-01, SIGN-02, SIGN-03
**Role:** ENTERPRISE (enterprise001)
**Status:** Pending

## Goal

Verify RSA key pair generation, data signing, and signature verification work end-to-end via `DigitalSignatureController` endpoints.

## Success Criteria

1. `POST /signature/keypair/generate` returns 200 with publicKey, keyId, status fields
2. `GET /signature/keypair` returns the generated key pair info (no private key exposed)
3. `POST /signature/sign` with report data returns 200 with signatureData field
4. `POST /signature/verify` with valid signature returns `{valid: true}`
5. `POST /signature/verify` with tampered data returns `{valid: false}`
6. `DELETE /signature/keypair` revokes the key pair successfully
7. DB verification: `rsa_key_pairs` table has record for enterprise001 after generation

## Approach

Single bash script following `scripts/credit-score-test.sh` pattern:
- Login as enterprise001 (ENTERPRISE role needed for sign/encrypt)
- Login as reviewer001 (REVIEWER role needed for verify)
- Core flow: generate → get → sign → verify(valid) → verify(tampered) → revoke
- Optional: encrypt/decrypt flow if time permits

## Implementation Steps

1. Create `scripts/sign-test.sh` with boilerplate (set -euo pipefail, helpers, BASE_URL)
2. Login as enterprise001, extract token
3. **SIGN-01:** `POST /signature/keypair/generate` — assert 200, assert publicKey present, assert keyId present
4. `GET /signature/keypair` — assert 200, assert publicKey matches generation response
5. DB check: `mysql -h 127.0.0.1 -P 3306` query `rsa_key_pairs` for enterprise001's userId
6. **SIGN-02:** `POST /signature/sign` with JSON report data — assert 200, assert signatureData present
7. Login as reviewer001 (or admin), extract token
8. **SIGN-03:** `POST /signature/verify` with correct data + signature — assert `{valid: true}`
9. `POST /signature/verify` with tampered data — assert `{valid: false}`
10. Cleanup: `DELETE /signature/keypair` as enterprise001 — assert 200
11. Summary with pass/fail counts

## Key Endpoints

| Endpoint | Method | Role | Purpose |
|----------|--------|------|---------|
| `/signature/keypair/generate` | POST | ENTERPRISE/REVIEWER/THIRD_PARTY | Generate RSA key pair |
| `/signature/keypair` | GET | ENTERPRISE/REVIEWER/THIRD_PARTY | Get current key pair info |
| `/signature/keypair` | DELETE | ENTERPRISE/REVIEWER/THIRD_PARTY | Revoke key pair |
| `/signature/sign` | POST | ENTERPRISE | Sign report data |
| `/signature/verify` | POST | REVIEWER/THIRD_PARTY/ADMIN | Verify signature |

## Risk Mitigation

- **JWT expiration:** Single script, short flow — unlikely to expire
- **Role mismatch:** sign requires ENTERPRISE, verify requires REVIEWER/ADMIN — use two accounts
- **Key already exists:** If enterprise001 already has a keypair, generate will revoke old one automatically (per controller docs)

## Verification

Run `bash scripts/sign-test.sh` — all tests should pass with 0 failures.
